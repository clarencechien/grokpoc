# 第七章 A/B：Grok CLI vs Gemini Omni 1.1 Flash

2026-09-28。拿影片版的第七章（萬箭齊發）做對照：**同樣的首格／末格圖、720p、16:9、6 秒**。
Grok 那一方是 `arrows/assets/` 裡原本就在用的片，Omni 那一方是這次新生成的。

- 看片：`arrows/ab_omni/index.html`（並排播放，Omni 有聲音）
- 生成：`scripts/omni_gen.py`（`POST /v1beta/interactions`，model `gemini-omni-1.1-flash`，金鑰取自 env `gemini_key`）
- 量測：`scripts/ab_compare.py` → `metrics.json`、`sheet_*.jpg`

## 測項

| 測項 | Omni 輸入 | Grok 對照 |
|---|---|---|
| rise | 首格 `ref_spread_blank.jpg`、末格 `c7.jpg` | `c7_rise.mp4`（收折片倒放） |
| turn | 首格 `c7.jpg`、末格 `ref_spread_blank.jpg` | `c7_turn.mp4`（只釘首格） |
| ambient | 首格 `c7.jpg` | `c7_ambient.mp4` |
| c6→c7 | 首格 `c6.jpg`、末格 `c7.jpg`，同一個 prompt 抽兩次 | `c6_turn.mp4` + `c7_rise.mp4` 兩支接起來 |

Prompt 都照 imagine skill 的規則寫成一個鏡頭、一個動作，並加上 `Soft paper sounds only, no music, no voices`（API 沒有關聲音的參數）。
完整 prompt 與回應（去掉 base64 與簽章）在 `omni_*.json`。

## 數字（程式量的，不靠眼睛）

| 測項 | 一方 | 首格差 | 末格差 | 背景晃動 | 動作峰 |
|---|---|---:|---:|---:|---:|
| rise | Grok | 13.5 | 2.1 | 6.2 | 2 |
| | Omni | **2.9** | 2.9 | **2.2** | 2 |
| turn | Grok | 2.1 | 9.8 | 11.4 | 2 |
| | Omni | 3.2 | **2.4** | **2.4** | 1 |
| ambient | Grok | 2.1 | 4.9 | 1.8 | 0 |
| | Omni | 3.6 | 5.3 | 1.5 | 2 |
| c6→c7 | Grok（兩支，12 秒） | 2.0 | 2.1 | 6.5 | 7 |
| | Omni 第一抽（6 秒） | 3.2 | 3.0 | 2.1 | 2 |
| | Omni 第二抽（6 秒） | 3.2 | 3.1 | 2.2 | 4 |

- 「差」＝該端影格和指定圖縮到 320×180 的平均絕對差（0–255）。參考值：c6 對 c7 是 18.7、c7 對空白母版是 20.2，所以 3 左右就是「同一張」。
- 「背景晃動」＝書以外的桌面、牆面相對第 0 格的最大漂移（鏡頭或書有沒有動）。

## 用眼睛看的結果

- **c6→c7 一鏡到底**：Grok 做不到，Omni 一支片就做完，但**兩抽只有一抽能用**。
  - 第一抽：翻起的頁背面又畫了一次 c6 的城樓，c6 人物憑空消失，3.5–4 秒之間背景直接換成 c7。兩端對，中間劇情不通。
  - 第二抽：掀頁 → 空白 → 紙雕立起，順序正確；但 c7 幾乎在 4.5→5.0 秒的半秒內跳出來，末格被釘死，時間不夠用。
- **rise**：兩家都可以。Omni 先立紙偶、再淡入背景畫。
- **turn**：兩家都只翻一次。Omni 結尾就是空白母版，Grok 的結尾書和光都偏掉了（影片版要靠淡入蓋接縫的原因）。
- **ambient**：兩家各錯一種。
  - Grok：背景畫保住了，但箭插成扇形，連曹操自己的望樓都中箭。
  - Omni：箭是真的飛進來再插上，動作好看很多；但背景畫上原本的箭 2 秒內被抹掉，地上多一支散箭。

## 其他

- 速度：每支 34–40 秒，4 支同時送沒有問題。
- 花費：依公開價 720p 每秒 $0.10，5 支 × 6 秒 ≈ **$3**（沒有看到實際帳單）。
- 聲音：5 支都有 AAC 音軌（平均 −34 到 −46 dB），API 關不掉，只能用 prompt 要求。還沒實際聽過內容。
- 沒有 seed：同 prompt、同首末格，兩抽走完全不同的劇情，無法重現。
- 回應的 usage 裡有 thought tokens 和數百 token 的文字輸出：模型會先自己改寫 prompt 再生成。

## 結論

1. **首末格是真的有用**：影片版的「收折片倒放」和「翻頁＋升起兩支接起來」兩個權宜之計都可以拿掉，接縫處不用再靠淡入去蓋；鏡頭也比 Grok 穩（背景晃動 2 左右 vs 6–11）。
2. **沒有消滅抽卡，只是把抽卡從兩端移到中間。** 首末格釘住後，中間仍然可能「換景」而不是「翻頁」（1/2）。§16 的重驗迴圈還是要做，只是檢查項少了「結尾是否空白」「揭露是否為本章」兩類。
3. 若要重做影片版，Omni 值得取代 Grok 當生成後端：每章一支 c(N-1)→cN 的首末格片，抽 2–3 次挑一支。
4. 對 `arrows3d/` 的判斷不變：翻頁、景深、互動交給 3D 引擎，不抽卡、可停格。Omni 適合拿來做預告片，或修補單一鏡頭。
