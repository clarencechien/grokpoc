# 草船借箭 · Three.js 立體書

同一個故事、同一批 Grok 素材，改由 Three.js 即時渲染成一本會翻的立體書。
**不再生成任何新圖或影片**，所有零件都從 `arrows/assets/` 既有的素材拆出來。

線上：`/arrows3d/`（要走 http，WebGL 不吃 `file://` 貼圖；本機用 `python3 -m http.server` 開）

---

## 為什麼回頭做這版：影片路線偏在哪

回頭讀 `lessons-learned.md` 與 `grok-learned.md` §6–16，影片路線花掉的時間幾乎都在補同一個缺口：
**「立體」和「翻頁」原本是幾何問題，我們卻把它交給影像模型去「畫」出來。**

| 我們遇到的問題 | 根源 | 在 3D 裡 |
|---|---|---|
| 翻頁片只能釘首格，末格靠「收折片倒放」補（§13） | 模型不知道書的幾何 | 翻頁是一個角度參數，首尾都是我們定的 |
| 翻兩次、人物被空白頁蓋掉、船在翻頁中滑動（§16） | 每支片都在抽卡，沒有 seed | 不抽卡，每次都一樣 |
| 要 VLM 當裁判、寫針對性的 regression 問題才抓得到錯 | 生成結果不可預測 | 錯了就是程式錯，改一次就好 |
| c5 多一個人、封面稻草兵五個 | 模型不肯照數量 | 場景由卡片組成，要幾個放幾個 |
| 讀者只能看，不能停在翻頁中間、不能換角度 | 影片是烤死的 | 拖曳就能慢慢掀頁；滑鼠移動會帶動視角 |
| 9 章 × 3 支片 ≈ 60 MB | 每個狀態都是影片 | 整本 ≈ 2.5 MB（含 Three.js） |

**分工改成：Grok 負責「紙上畫了什麼」，Three.js 負責「紙怎麼動」。**
影像模型很會畫一張好看的紙偶、一張好看的背景板；它不擅長的是跨格的幾何一致性——那正好是 3D 引擎的本業。

## 沿用了哪些素材

`scripts/arrows3d_prep.py` 把舊素材拆成零件（全部在 `arrows3d/assets/`）：

| 來源 | 拆出來的東西 | 怎麼拆 |
|---|---|---|
| `ref_spread_blank.jpg`（空白母版） | 地頁紙、背頁空白紙、書口破紙疊、木桌 | 地頁用四角反透視攤平（`cv2.warpPerspective`） |
| `ref_cover_closed.jpg` | 封面上的水墨小畫 | 同上，反透視攤平 |
| `<id>_collapse.mp4`（收折片） | **乾淨背景板** | 取「人物已倒下、背景還沒褪」的那一格，對原圖做色彩校正，人物以外的區域仍用原圖（較銳利） |
| `<id>.jpg`（各章跨頁） | 紙偶／道具卡片（26 張） | 每張卡給一個粗框，GrabCut 以「和空白母版／背景板的差異」當前景種子 |
| `ref_cast.jpg`（定裝表） | 落幕頁五人謝幕 | 同上 |

封面跨頁沒有收折片，背景用 inpaint 補掉人物後，再以 canvas 題上書名。
收折片原本是為了「倒放當升起」的權宜之計，在這裡意外成了最好的乾淨背景來源。

卡片在 3D 裡的位置直接從原圖推回來：腳底那一列像素經由地頁的四角 homography 換成地頁上的 (x, 深度)，
卡片大小用該深度的「每像素多寬」換算。所以預設視角下，每一章看起來就是當初那張 Grok 圖，
但它是真的有景深的——移動滑鼠就看得出來。

## 立體書機構（`template.html`）

書是 90° 桌曆式（跟影片版一樣：背頁立著、地頁平躺、由下往上翻）。

- **翻頁**：地頁繞書脊往上轉 φ = 0 → 90°，正面是地頁紙，背面是下一章的背景板；轉到直立就成了下一章的背頁。
- **舊場景的紙偶**：站在翻起的那頁上，隨頁面升起的同時往頁面的外緣倒下（β = 90°·(1−u)²，永遠不會穿過背頁），
  最後面朝下貼平在頁上；超出頁緣的部分用一個跟著頁面轉的 clipping plane 裁掉。
- **新場景的紙偶**：parallel fold——永遠和正在升起的那頁平行，所以會跟著頁面一起從平躺站起來，被那頁蓋在底下，不會穿模。
- 封面打開時，封面板就是那張「翻起的頁」，機構完全相同。
- 每一個 spread 狀態只是一個浮點數 `pos ∈ [-1, 9]`（-1 闔上、0 序、1–8 各章、9 全書完）；
  翻頁 = 用臨界阻尼彈簧把 `pos` 推向整數。拖曳時直接改 `pos`，所以可以停在翻頁的任何一個角度。

每章一個小動作，都是程式寫的，不是影片：
燈籠（點光源＋閃爍光暈）、c4 茶的熱氣與魯肅踱步、c5/c6 江霧、c6 擂鼓時紙偶跳動與畫面輕震、
**c7 真的有箭從背頁後方曹操那一側射出、呈拋物線插進草人**（插上的箭會跟著卡片一起倒下收進書裡）、
c8 稻草人歡呼跳躍、檯燈轉成晨光色。

## 建置

```bash
pip install pillow numpy opencv-python-headless scipy
python3 scripts/arrows3d_prep.py --sheet   # 拆素材；--sheet 另存剪紙對照圖到 assets/_check/（不進 git）
python3 scripts/build_arrows3d.py          # story 文字 + scenes.json 內嵌進 template → index.html
python3 -m http.server                     # 開 http://localhost:8000/arrows3d/
```

- Three.js r170 放在 `vendor/`（單檔 ES module，MIT），不依賴 CDN。
- 字體用 Google Fonts 的 Ma Shan Zheng（書名、「全書完」）；載不到就退回系統襯線字，不影響功能。
- 素材網址帶內容指紋 `?v=`（沿用影片版「新舊混雜」那次的教訓）。

## 驗證方式（沿用 lessons-learned §5 的原則）

- Headless Chromium（`--use-angle=swiftshader`）截圖 WebGL 畫面是可靠的——跟 CSS 捲動不同，
  它不會產生拼裝影格，因為整張圖是同一次 `render()` 畫的。
- 頁面掛了 `window.__book`（`pos`、`go(n)`、`jump(p)`）：`jump(0.5)` 可以把書凍在翻頁一半截圖；
  互動（點擊、方向鍵、滾輪、拖曳、頁碼點、再讀一次）用 DOM 狀態 `body[data-spread]`、`#cap` 的 display 判斷。
- 已驗：1280×720 與 390×844 兩種尺寸、9 個 spread 靜止畫面、多個翻頁中間角度、console 無錯誤。
- 未驗：真手機實機（觸控拖曳手感、效能）。

## 已知限制 / 下一步

- 卡片是從成圖裡剪出來的，所以帶著原圖的光影；3D 燈光再照一次，暗處偶爾偏髒。要更乾淨，下一輪可以請 Grok
  直接在素色紙上生「單一紙偶」（像 `ref_cast.jpg` 那樣），剪起來零瑕疵，表情也能照章節要。
- 背景板來自 720p 影片格，比原圖軟一些；被人物擋住的地方最明顯。
- c5 的船上仍有原圖那個多出來的白衣人（剪紙照原圖剪）。若改用單一紙偶組場景就能順手修掉。
- 沒有音效；翻頁聲、鼓聲、箭聲很適合用 WebAudio 補。
